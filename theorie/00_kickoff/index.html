Kursaufbau

Wie kommen wir zur Data-Story?

Extract Daten beschaffen
→
Transform Daten bereinigen
→
Load Daten speichern
→
Unload Daten ausgeben
→
Frontend Daten zeigen

Jeder Schritt ist eine eigene PHP-Datei mit genau einer Aufgabe.

Extract, Transform und Load werden in der Praxis so genannt und zu ETL abgekürzt.

Unload ist unser eigener Name für den Schritt danach.

Dieselbe Kette wie zwei Folien vorher, jetzt mit ihren richtigen Namen. Sie kommt in jedem weiteren Foliensatz als «Wo wir stehen» wieder. Hier bewusst nur benennen, jeder Schritt bekommt spaeter seinen eigenen Tag.

Direkt auf die Kette der Folie davor zurueckzeigen: Ab dem zweiten Punkt ist der Kursaufbau derselbe Weg wie der Weg der Daten. PHP Basics steht davor, weil es das Werkzeug fuer alles Weitere ist. Das Repo hier kurz oeffnen und zeigen, dass genau diese Reihenfolge auch dort steht.

Projekt

Der Auftrag in einem Satz

Ihr beantwortet eine Frage mit Daten, die ihr selbst beschafft, gespeichert und sichtbar gemacht habt.

Bewusst ohne Themenvorgabe. Das Thema entsteht gleich in der Themenboerse. Die Frage selbst wird erst spaeter scharf formuliert.

Vier Bestandteile

Daten

Zahlen, die eine Frage wirklich beantworten können.

Zeit

Ein Zeitraum, über den sich etwas verändert.

Darstellung

Eine Grafik, in der man die Veränderung sieht.

Einbettung

Text, der sagt, warum das jemanden angeht.

Die ersten beiden Teile beschafft ihr, die letzten beiden gestaltet ihr.

Diese vier Begriffe an der Wandtafel mit den Antworten aus dem Workshop abgleichen. Meist fehlt der Klasse der Punkt Zeit – genau der macht aus einer Tabelle eine Geschichte.

Was ihr dafür bauen werdet

Backend
  • Eine Datenquelle, die euch Zahlen liefert
  • Ein Skript, das diese Zahlen säubert
  • Eine Datenbank, die sie behält
  • Ein Endpunkt, der sie als JSON ausgibt
Frontend
  • HTML, CSS und JavaScript
  • Chart.js für die Grafik
  • Text, Titel und Quellenangaben
Beruhigend formulieren: Das Frontend koennt ihr bereits. PHP und Datenbank sind das Neue, und wir gehen sie in kleinen Schritten durch.

Woran ihr euch halten solltet

Eine Datenquelle

Nicht drei, auch wenn es verlockend klingt.

Ein kleines Datenmodell

Eine oder zwei Tabellen reichen völlig.

Ein JSON-Endpunkt

Er versorgt euer Frontend mit allem Nötigen.

Mindestens eine Grafik

Sie muss eure Frage beantworten, nicht beeindrucken.

Erfahrungsgemaess scheitern Projekte an zu grossen Plaenen, nie an zu kleinen. Diese vier Grenzen sind eine Hilfe, keine Strafe.

Gruppenbildung

Gruppenbildung

Ihr arbeitet zu viert und teilt euch in zwei Zweierteams:

Backend zu zweit

Ihr holt die Daten, säubert sie und speichert sie in der Datenbank.

Am Ende liefert ihr einen JSON-Endpunkt aus.

Frontend zu zweit

Ihr baut die Story und die Grafik.

Ihr startet mit erfundenen Daten und wechselt später auf den echten Endpunkt.

Damit das zusammenpasst, einigt ihr euch auf einen Datenvertrag.

Datenvertrag hier kurz erklaeren: die Vereinbarung, welche Felder die JSON-Ausgabe hat und wie sie heissen. Nur ankuendigen, festgehalten wird sie erst, wenn die ersten echten Daten da sind. Wichtig: Beide Zweierteams bleiben fuer das Ganze verantwortlich. Gebildet werden die Gruppen am Schluss des Halbtags in der Themenboerse.
