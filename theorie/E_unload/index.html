Was bedeutet «Unload»?

Unsere Kursbezeichnung

Daten aus der Datenbank lesen und als JSON ausgeben.

  • ETL endet normalerweise beim Laden
  • Unser Projekt braucht danach einen Weg zurück ins Frontend
  • unload.php ist dieser Weg
  • Die Datei liefert Daten und kein HTML

«Unload» ist hier ein praktischer Kursbegriff und kein zusätzlicher Buchstabe in ETL.

Den Begriff bewusst begrenzen, damit er später nicht als universeller Fachbegriff ausgegeben wird.

Der Browser fragt, PHP antwortet mit JSON

Browser oder fetch() braucht Daten
Anfrage GET /unload.php?city=Bern →
← Antwort [{"city":"Bern", …}]
unload.php liest die Datenbank

Der Browser bekommt am Ende nur JSON – hergestellt hat es unser PHP.

Eine fremde API wie aare.guru macht genau dasselbe: URL rein, JSON raus.

Neu ist nur, dass jetzt ihr die Seite mit dem PHP seid.

Beispiel zum Anschauen: aareguru.existenz.ch/v2018/current?city=bern
GET bedeutet hier: Daten anfordern, ohne den gespeicherten Stand zu verändern. Die aare.guru-URL im Browser öffnen und zeigen, dass dort auch nur ein Server JSON zurückgibt. Richtung sauber trennen: In Block B habt ihr mit fetchJson eine fremde API konsumiert, hier werdet ihr selbst zur API, die das Frontend konsumiert.

SQL

Nur die vereinbarten Felder lesen


SELECT
    c.name AS city,
    hs.year,
    hs.measurement_days,
    hs.hot_days,
    hs.max_temperature_c
FROM heat_summers AS hs
JOIN cities AS c ON c.id = hs.city_id
ORDER BY hs.year, c.name
  • SELECT * bleibt weg, weil der Endpunkt nur vereinbarte Felder ausliefert
  • AS city gibt dem Feld direkt den vereinbarten JSON-Namen
  • JOIN ergänzt den Stadtnamen aus der zweiten Tabelle
  • ORDER BY macht die Reihenfolge verlässlich
Die Reihenfolge ist Teil der Endpunkt-Entscheidung: zuerst Jahr, dann Stadt. Bei 258 Zeilen brauchen wir noch keine Begrenzung.
PHP

PDO macht aus Zeilen ein PHP-Array


require __DIR__ . '/../../../config.php';

$pdo = new PDO($dsn, $username, $password, $options);

$sql = "SELECT
            c.name AS city,
            ...
        ORDER BY hs.year, c.name";

$statement = $pdo->prepare($sql);
$statement->execute();

$rows = $statement->fetchAll();

$rows ist eine Liste assoziativer Arrays.

Die Schlüssel kommen aus dem SELECT.

Die Verbindung ist dieselbe wie beim Laden.

Baustein 3

Als JSON antworten

Der Browser bekommt Daten und sonst nichts

PHP

Die Antwort sagt, was sie enthält


header('Content-Type: application/json; charset=utf-8');
Content-TypeFormat der Antwort
→
application/jsongültiges JSON
+
charset=utf-8Zürich bleibt Zürich

Der Header muss vor jeder Ausgabe stehen.

Ein Leerzeichen oder eine Debug-Ausgabe vor header kann bereits die Meldung «headers already sent» auslösen.
PHP

json_encode macht aus dem Array JSON

PHP-Array
$data = [ ['city' => 'Bern', 'year' => 2023] ];
→
JSON-Text
[ {"city":"Bern","year":2023} ]

echo json_encode($data, JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE);
  • JSON_THROW_ON_ERROR macht Kodierungsfehler sichtbar
  • JSON_UNESCAPED_UNICODE hält Umlaute lesbar
JSON ist Text mit strengen Regeln, kein PHP-Array. Die Optionen sind bewusst in Grossbuchstaben, weil es Konstanten sind.

Kein gültiges JSON


var_dump($rows);
echo '<h1>Fertig</h1>';
echo json_encode($data);
array(258) { ... } <h1>Fertig</h1> [{"city":"Bern",...}]

Debug-Text und HTML zerstören die Antwort.

Eine reine Antwort


header('Content-Type: application/json; charset=utf-8');

echo json_encode($data, JSON_THROW_ON_ERROR);
[{"city":"Bern",...}]
Code Prediction: Welche der beiden Antworten kann JSON.parse verarbeiten? Danach die Trennlinie als Grenze zwischen Debug-Werkzeug und öffentlichem Endpunkt lesen.

Baustein 3 im Ausnahmefall

Leere Resultate und Fehler

Auch der Ausnahmefall antwortet als JSON

PHP

Kein Treffer ist kein Fehler

200 OK keine passenden Zeilen
[]
  • fetchAll() liefert bei null Treffern eine leere Liste
  • json_encode macht daraus []
  • Der Code braucht dafür keine Sonderbehandlung
  • Das Frontend kann dieselbe Listenlogik weiterverwenden

Für eine Listenabfrage ist [] die stabilste Antwort.

Leere Liste und technischer Fehler unterscheiden. Für einen einzelnen Datensatz wäre 404 denkbar, unser Endpunkt liefert aber immer eine Liste.
PHP

Auch ein Fehler antwortet als JSON


try {
    // verbinden, lesen und antworten
} catch (Throwable $error) {
    http_response_code(500);
    error_log($error->getMessage());

    echo json_encode([
        'error' => 'Daten konnten nicht geladen werden.',
    ]);
}

Interne Datenbankmeldungen gehören ins Server-Log und nicht in die öffentliche Antwort.

Im Unterricht absichtlich einen Tabellennamen falsch schreiben und die zwei Orte des Fehlers zeigen: kurze JSON-Antwort im Browser, genauer Text im Log.

Baustein 4

Den Endpunkt filtern

Die URL stellt eine kleine Frage an die Daten

URL + PHP

$_GET liest Werte aus der URL

GET/unload.php?city=Bern
Namecity
→
WertBern
→
PHP$_GET['city']

$city = trim($_GET['city'] ?? '');

?? '' setzt einen leeren String, wenn der Parameter fehlt.

Abgrenzung zu Extract: fetchJson sendet einen Request an eine fremde API. $_GET liest einen Parameter, den unser eigener Endpunkt erhält.
PHP + SQL

Der Filter ist optional


$sql = 'SELECT c.name AS city, hs.year, hs.measurement_days,
               hs.hot_days, hs.max_temperature_c
        FROM heat_summers AS hs
        JOIN cities AS c ON c.id = hs.city_id';

$params = [];

if ($city !== '') {
    $sql .= ' WHERE c.name = :city';
    $params['city'] = $city;
}

$sql .= ' ORDER BY hs.year, c.name';

Ohne city kommen alle Städte und mit city nur passende Zeilen.

Den SQL-Text für beide Fälle laut zusammensetzen lassen. Der Filter verändert die Auswahl, aber nie die Struktur der Antwort.
PHP

Der Wert bleibt vom SQL getrennt


$statement = $pdo->prepare($sql);
$statement->execute($params);

$rows = $statement->fetchAll();
SQL-Bauplan

WHERE c.name = :city

Werte

['city' => 'Bern']

Ohne Filter ist $params einfach eine leere Liste.

Das Muster ist dasselbe wie beim INSERT: prepare bekommt den Bauplan, execute bekommt die Werte.
Browser

Vier Aufrufe zeigen, ob der Vertrag hält

AufrufErwartung

Prüfe in der Entwicklerkonsole im Netzwerk-Tab zusätzlich den Statuscode und den Content-Type.

Die Zahlen gelten für den Hitzesommer-Code-Along mit drei Städten und 86 vollständigen Sommern von 1940 bis 2025.

Übertragt das Muster auf euren Endpunkt

  • Nur Felder aus dem Datenvertrag auswählen
  • Die JSON-Feldnamen im SELECT mit AS setzen
  • Eine feste und sinnvolle Sortierung setzen
  • Einen optionalen Filter als Prepared Statement bauen
  • Ohne Treffer eine leere Liste liefern
  • Fehler als JSON ohne interne Details beantworten
  • Keine HTML- oder Debug-Ausgabe mitsenden
  • Mock-JSON und echte Antwort im Team vergleichen

Fertig ist der Endpunkt, wenn das Frontend ohne Sonderlösung zwischen Mock und PHP wechseln kann.

Tagesabnahme in Paaren: Eine Person aus dem Frontend-Team testet den Endpunkt einer anderen Gruppe anhand dieser Liste.
