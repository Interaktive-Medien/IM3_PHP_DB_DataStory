Herunterladen oder live abrufen

Live abrufen und sammeln

Das Programm holt die Daten bei jedem Aufruf neu.

  • Immer aktuell
  • Nötig, wenn ihr über die Zeit sammelt
  • Ohne Internet keine Daten
  • Die Quelle kann sich ändern oder ausfallen
  • Am Anfang habt ihr sehr wenige Daten

Einmal herunterladen

Der Datensatz liegt als Datei bei euch im Projekt.

  • Funktioniert immer und überall
  • Grosse Datenmengen
  • Ihr könnt die Daten jederzeit ansehen
  • Datensatz veraltet mit der Zeit
Häufiges Missverständnis: „Live" klingt anspruchsvoller und ist deshalb besser. Stimmt nicht – historische Daten geben meist die stärkere Story. Live ist dann sinnvoll, wenn das Sammeln über Zeit selbst die Aussage ist.

  • Die Antwort habt ihr als Datei gespeichert

Vier Techniken, dasselbe Ziel

Eine JSON-Datei lesen


<?php
header('Content-Type: text/plain; charset=utf-8');

$json = file_get_contents('data/bern.json');   // Datei als Text
$data = json_decode($json, true);              // Text als PHP-Array

echo count($data['daily']['time']);
  • file_get_contents liest die ganze Datei als String
  • json_decode macht daraus ein PHP-Array
  • Der Pfad gilt relativ zur PHP-Datei, die gerade läuft

Das true in json_decode ist kein Detail.

Ohne dieses Argument bekommst du Objekte ($data->daily) statt Arrays ($data['daily']).

Der Header ist derselbe wie in den PHP-Basics: PHP ist hier Datenleser, nicht Webseiten-Bauer. Ohne ihn frisst der Browser die Zeilenumbrüche.

Zwei Listen, die zusammengehören

Open-Meteo liefert keine Liste von Datensätzen, sondern zwei gleich lange Listen.

so kommen die Daten an 

"time":               ["1940-01-01", "1940-01-02"]
"temperature_2m_max": [-0.7,         2.1]
so lesen wir sie 

$dates = $data['daily']['time'];
$temps = $data['daily']['temperature_2m_max'];

for ($i = 0; $i < 5; $i++) {
    echo $dates[$i] . ': ' . $temps[$i] . " °C\n";
}
  • time[0] gehört zu temperature_2m_max[0]
  • Weil beide Listen denselben Index brauchen, passt hier for besser als foreach
  • In unsere eigene Struktur bringen wir das erst im nächsten Schritt
Das ist die inhaltlich wichtigste Folie zu JSON. An der Tafel die beiden Listen untereinander schreiben und den gemeinsamen Index einzeichnen.

Eine Live-API lesen


// Vorbereiteter Helfer: holt eine URL und gibt die Antwort als PHP-Array zurück.
function fetchJson(string $url): array {
    $ch = curl_init($url);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
    curl_setopt($ch, CURLOPT_TIMEOUT, 10);
    $response = curl_exec($ch);
    return json_decode($response, true);
}

$url  = 'https://api.open-meteo.com/v1/forecast?latitude=46.948&longitude=7.447'
      . '&hourly=temperature_2m&forecast_days=1&timezone=Europe/Zurich';
$data = fetchJson($url);
  • Den cURL-Code musst du nicht auswendig können – nur benutzen
  • Das Ergebnis ist wieder ein PHP-Array mit zwei parallelen Listen

cURL ist ein ausgehender Aufruf von unserem Server an eine fremde API.

Die Richtung des Aufrufs an der Tafel zeigen: ein Pfeil vom Browser auf unseren Server, ein zweiter von unserem Server weg zur fremden API. Später in Block E kommt mit $_GET die Gegenrichtung dazu – erfahrungsgemäss wird das jedes Jahr verwechselt.

Eine CSV-Datei lesen


$handle = fopen('data/attacks.csv', 'r');

// Kopfzeile = Spaltennamen
$header = array_map('trim', fgetcsv($handle, null, ',', '"', ''));

$attacks = [];
while (($row = fgetcsv($handle, null, ',', '"', '')) !== false) {
    if ($row[0] === '') {
        continue;                 // leere Zeile überspringen
    }
    $attacks[] = array_combine($header, $row);
}
fclose($handle);
  • CSV ist eine Tabelle als Text
  • Die erste Zeile enthält die Spaltennamen
  • fgetcsv liest genau eine Zeile
  • array_combine verbindet Spaltennamen und Werte
  • So entsteht ein Datensatz pro Zeile

Die Argumente ',' '"' '' sind die Standardwerte und stehen nur da, damit neuere PHP-Versionen nicht warnen.

Kurz zeigen, was array_combine macht: oben die Namen, unten die Werte, Reissverschluss. Danach hat man dieselbe Struktur wie bei JSON.

Echte Daten sind unordentlich

Was im Shark-Datensatz steckt

  • Rund 25'000 Zeilen
  • Davon etwa 8'700 echte Vorfälle
  • Der Rest sind leere Zeilen
  • Spaltennamen mit Leerzeichen wie "Species "
  • Teils doppelte Spalten

Was wir dagegen tun

  • trim() räumt die Spaltennamen auf
  • continue überspringt leere Zeilen
  • Sonst nichts

Hier räumen wir nur so weit auf, dass das Einlesen funktioniert.

Datumsformate, fehlende Werte und Kategorien kommen im nächsten Schritt dran: Transform.

Global Shark Attack File (GSAF), via Kaggle.
Guter Moment für Erwartungsmanagement im Projekt: Wer eine echte Quelle nimmt, verbringt mehr Zeit mit Aufräumen als mit Programmieren.

Die Sensorbox im Raum

  • Die Box misst laufend, zum Beispiel Temperatur, Luftfeuchtigkeit und CO₂
  • Sie stellt ihre Werte über HTTP als JSON bereit
  • Technisch ist sie damit einfach eine kleine eigene API
  • Wir holen die Daten mit demselben fetchJson()-Helfer

Die anderen drei Quellen liefern fremde Daten.

Hier messt ihr selber – der Unterschied ist inhaltlich gross und technisch klein.

  • Wer selber misst, besitzt die Quelle und kann die Datenfrage frei stellen
  • Wer selber misst, muss früh anfangen zu sammeln
  • Hardware und Programmierung der Box sind nicht Inhalt dieses Kurses
Box im Raum herzeigen und die Endpunkt-URL einmal im Browser öffnen. Ausblick: Solche Boxen können in einem späteren Kurs selbst gebaut werden.

Quelle prüfen

Bevor ihr euch festlegt

Woran ihr eine brauchbare Quelle erkennt

  • Zugang: ohne Anmeldung und ohne API-Key erreichbar
  • Format: JSON oder CSV, nicht PDF und nicht Bild
  • Menge: genug Datensätze für eine Aussage
  • Zeitraum: passt zu eurer Datenfrage
  • Felder: dokumentiert oder selbsterklärend benannt
  • Herkunft: Wer hat gemessen, wann und wie?
  • Lizenz: Weiterverwendung ist erlaubt
  • Grenzen: Was fehlt in diesen Daten?

Prüft die Quelle, indem ihr sie einmal im Browser öffnet und wirklich hineinschaut.

Eine schöne Projektseite sagt nichts darüber aus, ob die Daten brauchbar sind.

Diese Liste ist gleichzeitig die Abnahmegrundlage für den Meilenstein am Ende des Tages. Gruppen sollen zu jedem Punkt eine Antwort geben können.

Häufige Fehler

  • Datei nicht gefunden: der Pfad gilt relativ zur laufenden PHP-Datei
  • Objekte statt Arrays: das true bei json_decode vergessen
  • Alles auf einer Zeile: der Content-Type-Header fehlt
  • Leere Antwort von der API: zuerst die URL im Browser aufrufen
  • Undefined key: Schlüssel falsch geschrieben oder eine Ebene übersprungen
  • Verschobene Werte: die Kopfzeile der CSV mitgezählt
  • Spalte existiert nicht: Leerzeichen im Spaltennamen
  • Nichts passiert: die Datei per Doppelklick statt über http:// geöffnet

Erster Griff bei jedem Problem: var_dump oder print_r auf die Variable, statt zu raten.

Bei „Undefined key" immer zuerst array_keys() auf die Ebene darüber – das löst gefühlt die Hälfte aller Fälle.
