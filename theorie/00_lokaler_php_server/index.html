  • Dort liegen PHP-Dateien und Datenbank zusammen
  • PhpStorm lädt dann jede gespeicherte Datei hoch
  • Dort muss das Projekt am Marktstand laufen

Das hier ist eure Arbeitsumgebung, bis die Datenbank dazukommt.

Alle Code-Alongs und Übungen bis dahin setzen sie voraus.

Lokal läuft der Kurs bis und mit Block C. Ab Block D arbeiten alle auf dem Webserver bei Hostpoint, weil dort PHP und Datenbank nebeneinander liegen: PhpStorm lädt jede gespeicherte Datei per FTP hoch, eingerichtet über die YouTube-Playlist. Für die Grundlagen bleibt es bewusst lokal, weil das Hochladen beim Ausprobieren früher am meisten Zeit gekostet hat. Deshalb hier nicht weitergehen, bevor alle eine laufende Ausgabe im Browser haben. Wer hängen bleibt, meldet sich sofort und wartet nicht bis zur Pause.

Zuerst prüfen, ob PHP schon da ist

Terminal öffnen und eintippen:


php -v
so sieht gut aus
PHP 8.3.6 (cli)

Dann seid ihr fertig mit dem Installieren.

so fehlt es noch
command not found: php

Dann kommt jetzt die Installation.

Terminal heisst auf Windows Eingabeaufforderung oder PowerShell.

Diesen Schritt wirklich machen lassen, bevor irgendjemand etwas herunterlädt. Auf manchen Rechnern ist PHP längst da, etwa über XAMPP oder eine ältere Installation. Wir empfehlen Version 8.1 oder neuer.

Der Auftrag zum Kopieren

Ich brauche PHP auf diesem Rechner, um ein Schulprojekt lokal im Browser zu testen. - Prüfe, ob PHP schon installiert ist. - Wenn nicht, installiere PHP 8.1 oder neuer. - Zeig mir danach, wie ich den eingebauten Testserver starte. - Erkläre mir jeden Schritt, bevor du ihn ausführst. Mein Betriebssystem ist macOS.

Die letzte Zeile anpassen, wenn ihr Windows benutzt.

Die erste Zeile im Auftrag ist wichtig: Ohne sie installiert der Agent unter Umständen ein zweites PHP neben das vorhandene. Danach prüft ihr selbst mit php -v, ob wirklich eine Versionsnummer erscheint – und zwar in einem neu geöffneten Terminalfenster.

Server starten

1. Kursordner in PhpStorm öffnen und das Terminal starten
View → Tool Windows → Terminal

Kürzel: ⌥ + F12, unter Windows Alt + F12.

Das Terminal startet direkt im Kursordner.

2. Server starten 

php -S localhost:8000

Der Server läuft, solange das Terminal offen ist – beenden mit Ctrl + C.

Damit ist der Agentenweg zu Ende – wer hier ankommt, überspringt das nächste Kapitel und macht bei «Was der Befehl bedeutet» weiter. Diesen Befehl hat der Agent vermutlich bereits genannt; ihn hier trotzdem einmal selbst eintippen zu lassen ist Absicht, sie brauchen ihn ab jetzt jeden Tag.

Von Hand

Wenn ihr keinen Agenten habt

PHP installieren – macOS

Neuere macOS-Versionen liefern kein PHP mehr mit.

1. Homebrew prüfen, dem Paketmanager für den Mac 

brew -v
2. Falls er fehlt, Homebrew installieren 

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
3. PHP installieren und prüfen 

brew install php
php -v
Homebrew fragt beim Installieren nach dem Passwort des Rechners und läuft danach einige Minuten. Am Ende gibt es Hinweise im Terminal, die man tatsächlich lesen muss – manchmal steht dort ein Befehl, der noch auszuführen ist. Ein Paketmanager ist ein Programm, das andere Programme installiert und aktuell hält.

PHP installieren – Windows

  1. Auf windows.php.net die aktuelle Zip-Version unter «Thread Safe» herunterladen
  2. Das Zip in einen einfachen Ordner entpacken, zum Beispiel C:\php
  3. In der Windows-Suche «Umgebungsvariablen bearbeiten» öffnen
  4. Bei Path auf Bearbeiten, dann Neu, dann C:\php eintragen
  5. Ein neues PowerShell-Fenster öffnen und php -v eingeben

Der PATH sagt Windows, wo es den Befehl php suchen soll.

Alternative: XAMPP installieren, das bringt PHP fertig mit.

Der häufigste Fehler steht in Schritt fünf: Ein bereits offenes Terminal kennt den neuen PATH nicht, auch das Terminal in PhpStorm nicht. Wer XAMPP nimmt, kann trotzdem mit dem eingebauten Server von der nächsten Folie arbeiten und muss den Apache von XAMPP nicht benutzen.

Server starten

1. Kursordner in PhpStorm öffnen und das Terminal starten
View → Tool Windows → Terminal

Kürzel: ⌥ + F12, unter Windows Alt + F12.

Das Terminal startet direkt im Kursordner.

2. Server starten 

php -S localhost:8000

Der Server läuft, solange das Terminal offen ist – beenden mit Ctrl + C.

Weil das Terminal von PhpStorm schon im Kursordner startet, entfällt das Abtippen von Pfaden – das spart erfahrungsgemäss die meiste Zeit. Wichtig zu betonen: Nach einer Änderung an einer Datei genügt im Browser ein Neu laden, der Server muss nicht neu gestartet werden.

Was der Befehl bedeutet


php -S localhost:8000
  • php ist das PHP-Programm
  • -S startet den eingebauten Testserver, mit grossem S
  • localhost ist euer eigener Rechner
  • 8000 ist die Portnummer, also die Tür

Ist die Tür belegt, nehmt ihr eine andere: php -S localhost:8080.

Der Begriff Port taucht hier zum ersten Mal auf und kommt bei der Datenbank wieder – dort ist es 8889. Deshalb lohnt sich das Bild mit der Tür: dieselbe Adresse, verschiedene Türen für verschiedene Dienste.

Im Browser aufrufen

Startseite des Ordners
http://localhost:8000
Datei in einem Unterordner
http://localhost:8000/00_hallo_php/index.php

Öffnet die Datei nie per Doppelklick.

Dann steht file:// in der Adresszeile und ihr seht den Code statt das Ergebnis.

Der Doppelklick-Fehler passiert in jedem Durchgang: Die Seite zeigt dann den PHP-Quelltext, weil niemand ihn ausgeführt hat. Die Faustregel dazu ist einfach – steht in der Adresszeile nicht localhost, läuft kein PHP.

Wenn es nicht läuft

Meldung oder Symptom Ursache
command not foundPHP ist nicht installiert oder nicht im PATH
Failed to listen on ...:8000Der Port ist belegt, andere Nummer nehmen
Browser zeigt den PHP-CodeDie Datei wurde per Doppelklick geöffnet
Not FoundFalscher Dateiname oder falscher Startordner
Nichts passiert nach dem SpeichernIm Browser neu laden, nicht den Server neu starten

Bleibt es dabei, meldet euch sofort – ohne laufenden Server geht es nicht weiter.

Bei «Not Found» hilft die Rückfrage, in welchem Ordner der Server gestartet wurde: php -S liefert immer nur den Ordner aus, in dem es läuft. Gross- und Kleinschreibung im Dateinamen zählt auf dem Webserver, auf dem Mac lokal oft nicht – das erzeugt Fehler, die erst beim Deployment am Schluss auftauchen. Deshalb von Anfang an konsequent kleinschreiben.
