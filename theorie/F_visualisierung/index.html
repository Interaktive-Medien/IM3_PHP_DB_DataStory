Erst die Aussage, dann der Diagrammtyp

Ein Diagrammtyp ist eine Behauptung über die Daten.

Eine Linie behauptet, dass die Punkte zusammenhängen und aufeinander folgen.

Ein Balken behauptet, dass sich Längen sinnvoll vergleichen lassen.

Ein Kreis behauptet, dass die Teile zusammen ein Ganzes ergeben.

Wer zuerst den Typ wählt, sucht danach Daten, die dazu passen.

Phasenregel aus dem Data Story Deck, Phase 6 «Datengrafiken»
Frage an die Klasse, bevor die Sätze eingeblendet werden: Was behauptet eine Linie eigentlich? Antwort: dass zwischen zwei Punkten etwas passiert ist und dass die Reihenfolge stimmt. Deshalb ist eine Linie über zehn Ländernamen falsch. Hier auf das Kartenset verweisen, das im UX-Teil verwendet wird.

Welches Diagramm?

Sechs Absichten, sechs Familien

Einteilung aus dem Data Story Deck, Phase 6 «Datengrafiken»
Diese sechs Absichten stehen auf der Titelkarte von Phase 6 im Kartenset. Frage an die Klasse: Welche Absicht hat eure Datenfrage? Die meisten Projekte landen bei Vergleich oder Entwicklung. Wer keine Absicht benennen kann, hat noch keine Datenfrage, sondern einen Datensatz.

Zwei Fragen an dieselben Daten

Entwicklung

«Nimmt die Zahl der Hitzetage zu?»

Die Jahre folgen aufeinander, also verbindet die Linie sie zu Recht.

type: 'line'

Vergleich

«Welches waren die heissesten Sommer?»

Eine Rangliste hat keine Reihenfolge in der Zeit, also Balken.

type: 'bar'

Dieselben 258 Datensätze, zwei Absichten, zwei Diagrammtypen.

Gegenprobe laut durchspielen: Die zehn heissesten Sommer als Linie würde behaupten, dass 2003 in 2015 übergeht. Das ist inhaltlich falsch, auch wenn es hübsch aussieht. Genau diese zwei Diagramme entstehen in den beiden Code-Alongs.

Kapitel 2

Von den Daten zum Diagramm

Der Bauplan und die eine wichtige Umformung

HTML + JS

Ein Diagramm braucht drei Dinge

im HTML: die Bibliothek und eine Zeichenfläche 

<script src="https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js"></script>
<canvas id="verlauf"></canvas>
im JavaScript: der Auftrag an Chart.js 

const chart = new Chart(document.querySelector('#verlauf'), {
  type: 'line',                          // welcher Diagrammtyp
  data: { labels: [], datasets: [] },    // was gezeigt wird
  options: verlaufOptions,               // wie es aussieht
});
Drei Schlüssel, mehr ist es nicht: type, data, options. options ist Fleissarbeit und steht im Code-Along fertig da – der Lernstoff steckt in data. Die Version im CDN-Link ist bewusst festgeschrieben, damit sich das Diagramm nicht über Nacht anders verhält.
JavaScript

Chart.js braucht ein bestimmtes Datenformat

was der Endpunkt liefert 

[
  {"city": "Bern", "year": 1940, "hot_days": 0},
  {"city": "Bern", "year": 1941, "hot_days": 1},
  {"city": "Bern", "year": 1942, "hot_days": 0}
]
→
was Chart.js will 

labels: [1940, 1941, 1942]

data:   [0, 1, 0]

Zwei Listen, gleich lang und in derselben Reihenfolge.

Das ist die Kernfolie des ganzen Inputs. Wer diese Umformung versteht, kann jedes Chart.js-Diagramm bauen; alles andere ist Nachschlagen. Nachfrage an die Klasse: Was passiert, wenn die beiden Listen unterschiedlich lang sind? Antwort: Chart.js zeichnet trotzdem, und die Werte stehen bei den falschen Jahren.
JavaScript

Eine Stadt wird eine Linie


function yearsOf(rows) {
  return [...new Set(rows.map((row) => row.year))].sort((a, b) => a - b);
}

function datasetFor(rows, city) {
  const cityRows = rows.filter((row) => row.city === city);

  return {
    label: city,
    data: cityRows.map((row) => row.hot_days),
    borderColor: CITY_COLORS[city],
  };
}

Ein dataset ist eine Linie: die Zahlen und ihr Aussehen.

new Set wirft die dreifach vorkommenden Jahre weg, sort mit Vergleichsfunktion bringt sie in die richtige Reihenfolge. Die Frage, die man leicht überspringt: Warum passen die Werte zu den Jahren? Weil der Endpunkt nach Jahr sortiert und jede Stadt jeden Sommer hat – geprüft haben wir das beim Transformieren.

Kapitel 3

Die Daten holen

Der eigene Endpunkt, gelesen mit fetch()

JavaScript

Der Browser fragt euren eigenen Endpunkt ab


const response = await fetch('unload.php?city=Bern');
const summers = await response.json();

Dieselben zwei Zeilen wie bei jeder fremden API im letzten Semester.

Neu ist nur, dass die API diesmal von euch stammt.

Der $_GET-Filter aus dem Endpunkt wird hier zum ersten Mal wirklich benutzt.

await braucht type="module" im script-Tag – das steht im Cheatsheet aus IM2 und ist im Code-Along schon gesetzt. Die Kette einmal laut durchgehen: Auswahl im Browser, ?city=Bern, WHERE im SQL, kleinere JSON-Antwort, neues Diagramm. Vier Blöcke Arbeit in einem Klick.
JavaScript

Nicht jede Antwort ist die erwartete


if (!response.ok) {
  throw new Error(`Der Endpunkt antwortet mit Status ${response.status}.`);
}

const contentType = response.headers.get('content-type') ?? '';

if (!contentType.includes('application/json')) {
  throw new Error('Die Antwort ist kein JSON.');
}

fetch() wirft bei Status 404 oder 500 keinen Fehler – es ist ja eine Antwort angekommen.

Öffnet ihr die Seite nicht über eure Domain, kommt statt JSON etwas anderes zurück.

Hier lohnt sich die Demo: Seite einmal per Doppelklick oder über das Browser-Symbol von PhpStorm öffnen und zeigen, was zurückkommt. Der Content-Type-Header aus dem Endpunkt ist genau dafür da. Merkregel für die Klasse: In der Adressleiste steht die eigene Domain, nicht localhost.
JavaScript

Die Übergabe ist eine einzige Zeile

beim Bauen 

const DATEN_URL = MUSTERDATEN;   // data/heat-summers.json
nach der Übergabe 

const DATEN_URL = ENDPUNKT;      // unload.php

Das Frontend-Team baut mit einer Musterdatei, lange bevor das Backend fertig ist.

Am Schluss wechselt eine Zeile, und dem Diagramm sieht man nichts an.

Das funktioniert nur, weil beide Seiten denselben Datenvertrag eingehalten haben.

Wenn beim Umschalten etwas bricht, war der Vertrag nicht eingehalten – das ist die eigentliche Abnahme zwischen den beiden Teams. Zweiter Nutzen derselben Datei: Sie ist der Fallback für den Marktstand, wenn die Datenbank streikt.

Kapitel 4

Auf Bedienung reagieren

Aktualisieren statt neu erzeugen

Chart.js

Einmal erzeugen, danach aktualisieren


const chart = new Chart(canvas, { type: 'line', data: leer, options });

function render() {
  chart.data.labels = yearsOf(summers);
  chart.data.datasets = cityNamesOf(summers).map((city) => datasetFor(summers, city));
  chart.update();
}

Ein zweites new Chart() auf demselben Canvas meldet «Canvas is already in use».

Das ist der häufigste Anfängerfehler mit Chart.js. Wer das Diagramm bei jeder Änderung neu erzeugt, verliert ausserdem die Animation und den Zustand der Legende. update() zeichnet nur, was sich geändert hat.

Zwei Sorten Interaktion

Der Server antwortet neu

Die Stadtauswahl schickt eine neue Anfrage.

change → fetch('unload.php?city=Bern')
→ SELECT → render()
Der Browser rechnet selbst

Der Zeitraum-Schieber benutzt Daten, die schon da sind.

input → fromYear ändern
→ render()

Der Server filtert, was viel ist – der Browser filtert, was schon da ist.

Bei 258 Zeilen wären beide Wege richtig. Bei 200'000 Zeilen ginge nur noch der Server, und bei einem Schieber, der bei jeder Bewegung feuert, nur noch der Browser. Im Code-Along steht der Unterschied als Hinweis unter jedem Bedienelement, und im Netzwerk-Tab wird er sichtbar.
JavaScript

Ein Zustand, eine Zeichenfunktion


let summers = [];          // was geladen ist
let fromYear = 1940;       // welcher Ausschnitt
let metric = 'hot_days';   // welcher Messwert

Jedes Bedienelement ändert genau eine dieser Variablen und ruft dann render() auf.

So steuern drei Bedienelemente zwei Diagramme, ohne dass der Code unübersichtlich wird.

render() ist die einzige Stelle, die ein Diagramm anfassen darf.

Die Alternative wäre, in jedem Listener am Diagramm herumzubauen. Das funktioniert bei einem Bedienelement und wird beim dritten unlesbar. Wer diese Trennung einmal gesehen hat, erkennt sie in jedem Frontend-Framework wieder.

Kapitel 5

Karten mit Leaflet

Dieselbe Kette, eine andere Zeichenbibliothek

Richtwert: 8 Minuten für dieses Kapitel. Wichtig für die Rahmung: Alles aus den Kapiteln 2 bis 4 gilt weiter. Nur der letzte Schritt wechselt das Werkzeug. Wer die Klasse abholen will, blättert kurz zur Tabelle in Kapitel 1 zurück – dort stand Leaflet schon als Antwort, jetzt lösen wir das Versprechen ein.
HTML + JS

Leaflet braucht nur drei Dinge

im HTML: zwei Dateien und ein Behälter mit Höhe 

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/leaflet@1.9.4/dist/leaflet.css">
<script src="https://cdn.jsdelivr.net/npm/leaflet@1.9.4/dist/leaflet.js"></script>
<div id="karte"></div>      /* im CSS: height: 520px */
im JavaScript: Ausschnitt, Hintergrund, Daten 

const karte = L.map('karte').setView([20, 0], 2);
L.tileLayer(kachelUrl, { attribution: quelle }).addTo(karte);
L.geoJSON(grenzen, { style: stilFuer }).addTo(karte);

Ohne Höhe im CSS bleibt die Karte unsichtbar, und die Konsole meldet nichts.

Die Parallele laut aussprechen: type, data, options hiess bei Chart.js «welcher Typ, was, wie». Hier heisst es «welcher Ausschnitt, welcher Hintergrund, welche Daten». Zwei Unterschiede betonen. Erstens braucht Leaflet auch ein Stylesheet – fehlt es, liegen alle Kacheln übereinander in der Ecke, und das sieht nach einem Fehler im eigenen Code aus. Zweitens der Behälter: canvas hat eine eigene Grösse, ein leeres div ist 0 Pixel hoch. Der häufigste Leaflet-Fehler überhaupt, und er meldet sich nirgends. Die attribution ist keine Höflichkeit, sondern Bedingung der Kachel-Anbieter.

Die Umrisse der Länder sind GeoJSON

Leaflet kennt keine Länder, es liefert nur den Hintergrund.

laender.geojson, ein Eintrag pro Land 

{
  "type": "Feature",
  "properties": { "iso3": "AUS", "name": "Australia" },
  "geometry": {
    "type": "Polygon",
    "coordinates": [[[145.4, -40.8], [146.8, -41.0], ...]]
  }
}

geometry ist der Umriss als Liste von Punkten, properties sind die Angaben zum Land.

woher ihr die Datei bekommt
  • Weltkarte: Natural Earth, gratis und frei nutzbar
  • Schweiz: swisstopo, Kantone und Gemeinden
  • Sonst: nach «<Gebiet> geojson» suchen

Auch eine Kartendatei ist ein Datensatz, den ihr kürzen dürft.

naturalearthdata.com, «Admin 0 – Countries» in 1:110m, Public Domain
Die Frage zuerst stellen: Woher weiss der Browser eigentlich, wo Australien aufhört? Antwort: gar nicht. Der Umriss muss als Datei mitkommen, so wie jede andere Zahl auch. Die Koordinaten kurz zeigen und dann wieder zuklappen – niemand liest sie, und genau das ist die Botschaft: Man arbeitet mit properties, nicht mit geometry. Zur Auflösung: 1:110m ist die grobe Weltstufe und genügt für eine Übersichtskarte. 1:50m ist genauer und dreimal so gross, was im Browser sofort spürbar wird. Unsere Datei wurde von 168 Eigenschaften pro Land auf zwei gekürzt. Das ist derselbe Transform wie beim eigenen Datensatz, nur an fremdem Material. Für die Projekte: Wer Schweizer Gemeinden braucht, findet sie bei swisstopo und im Repo swiss-maps auf GitHub.
JavaScript

Verbunden wird über einen Schlüssel

was euer Endpunkt liefert 

{
  "country": "USA",
  "iso3": "USA",
  "incidents": 1486,
  "top_species": "White shark"
}
→
was in der Kartendatei steht 

{
  "properties": {
    "iso3": "USA",
    "name": "United States of America"
  }
}

Zwei Dateien aus verschiedenen Quellen passen zusammen, weil beide denselben Ländercode kennen.

Das ist die Kernfolie dieses Kapitels, das Gegenstück zu «Chart.js braucht ein bestimmtes Datenformat». Bei Chart.js war die Verbindung die Reihenfolge zweier gleich langer Listen. Hier ist sie ein Schlüssel, der in beiden Dateien vorkommt. Rückblick auf den Transform: Genau deshalb wurde dort aus «USA» ein ISO-Code nachgeschlagen und nicht bloss der Name behalten. Namen sind Schreibweisen, Codes sind Schlüssel. Frage an die Klasse: Was ist der Schlüssel in eurem Projekt? Bei Gemeinden die BFS-Nummer, bei Kantonen das Kürzel.
PHP

Den Ländercode legt eine Tabelle fest

Im Rohdatensatz steht nur ein Name, und Namen sind Schreibweisen.

laender_iso.json: Name → Code nachgeschlagen wird beim Transform 

{
  "USA": "USA",
  "AUSTRALIA": "AUS",
  "SOUTH AFRICA": "ZAF",
  "PAPUA NEW GUINEA": "PNG"
}
            

$value = strtoupper(trim($raw));

return $isoByCountry[$value] ?? null;

Die Tabelle entsteht aus den häufigsten Rohwerten, nicht aus dem Gedächtnis.

Fehlt ein Name in der Tabelle, bleibt null stehen.

Ohne Ländercode findet das Land seine Fläche nicht und bleibt grau.

Diese Folie beantwortet die Frage, die auf der vorigen entsteht: Woher kommt der iso3 in unseren Daten? Nicht aus der Quelle – die kennt nur «AUSTRALIA» als Text. Die Tabelle im Code-Along hat 50 Einträge und ist bewusst unvollständig. Sie entstand aus der Liste der häufigsten Rohwerte, nicht aus dem Gedächtnis. strtoupper und trim sind der Grund, warum «australia » und «AUSTRALIA» denselben Code finden. Das ?? null ist die Haltung aus dem Transform: nicht raten, sondern zugeben, dass wir es nicht wissen. Kanada steht nicht in der Tabelle und ist deshalb grau, obwohl es einen Vorfall gibt. Für die Projekte: Kantone haben Kürzel, Gemeinden die BFS-Nummer, Länder den ISO-3-Code.
Leaflet

Die Klassengrenzen sind eine Entscheidung

die Daten
USA 1486 AUSTRALIA 540 SOUTH AFRICA 322 ... über 60 Länder 1

Ein linearer Farbverlauf färbt nur die USA dunkel.

darum Klassen 

const KLASSEN = [
  { ab: 500, farbe: '#2f6b7a' },
  { ab: 100, farbe: '#4b93a4' },
  { ab:  50, farbe: '#7db0bd' },
  { ab:  20, farbe: '#a8c9d2' },
  { ab:   5, farbe: '#cfe0e5' },
  { ab:   1, farbe: '#eef4f6' },
];

Wer die Grenzen verschiebt, ändert die Aussage der Karte, ohne eine Zahl anzufassen.

Anknüpfen an die Histogramm-Zeile aus Kapitel 1: Klassen bilden ist Datenarbeit und nicht Sache der Grafikbibliothek. Dort war es der Grund, warum Chart.js kein Histogramm kann – hier ist es dieselbe Aufgabe noch einmal. Eine Farbe in sechs Helligkeiten, nicht sechs verschiedene Farben: Dunkler heisst mehr, und das versteht man ohne Legende. Wer mehr will, nennt die Verfahren gleiche Breite, Quantile und Jenks. Für den Kurs genügt eine begründete Wahl von Hand, aufgeschrieben in der Bildlegende.

Eine Weltkarte sieht aus wie die Wahrheit

  • Grau heisst «keine Zahl», nicht «nichts passiert»
  • Grosse Länder fallen auf, auch wenn dort wenig passiert
  • Kleine Inselstaaten verschwinden, obwohl sie zuoberst stehen
  • Wo niemand zählt, bleibt die Karte hell

Was die Karte nicht zeigt, gehört als Satz unter die Karte.

Der wichtigste Punkt des Kapitels, deshalb steht er am Schluss. Konkret im Code-Along: Réunion hat 53 Vorfälle und in der Kartendatei gar keine Fläche. Die Bahamas stehen auf Platz 6 und sind kaum zu sehen. Somalia ist hell, weil dort niemand zählt. Der Grönland-Effekt gehört dazu: Die übliche Projektion macht Länder im Norden viel zu gross. Frage in die Klasse: Welches Land fällt auf dieser Karte am meisten auf, und wie viele Vorfälle hat es? Meist wird Russland oder Kanada genannt – beide praktisch ohne Vorfälle. Hinweis auf die Lösung im Code-Along: Der Satz unter der Karte wird gerechnet und nicht hingeschrieben, damit er nicht irgendwann falsch ist.

  • Zwei Diagrammtypen vergleichen, bevor ihr einen wählt

Ein Diagramm, das seine Aussage ohne Klick zeigt, ist besser als eines, das sie versteckt.
